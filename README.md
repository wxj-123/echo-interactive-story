# 回声 ECHO · AIGC 互动影游

> 你是记忆修复师。而这间屋子里，有一片记忆不是你的。

一个 30 分钟左右的悬疑互动小说。玩家通过选择与**自由行动输入**推动剧情，走向 3 个完全不同的结局。

- 36 个剧情节点，7,200 余字正文
- 2 个关键岔路 + 3 个自由行动点
- 3 个结局（其中一个是隐藏的真结局）
- 模型参与运行时叙事裁定，**没有 API Key 也能完整通关**

---

## 快速开始

```bash
npm install
npm run serve
```

然后打开 <http://localhost:3001>。

`npm run serve` 会依次做三件事：校验剧情图 → 构建前端 → 启动服务（同端口托管页面与 API）。

### 想接入真模型（可选）

默认**不需要任何 Key** 就能玩通全流程。要体验模型参与的叙事裁定：

```bash
# 把 .env.example 复制为 .env，填入 OpenAI 兼容端点的 Key
LLM_BASE_URL=https://api.openai.com/v1
LLM_API_KEY=sk-xxxx
LLM_MODEL=gpt-4o-mini
```

重启后访问 `/api/health` 可以看到 `"llm": { "enabled": true }`。

### 开发模式

```bash
npm run dev     # 前端 5173 + API 3001，热更新
```

| 命令 | 作用 |

| `npm run validate` | 剧情图体检：断链、死胡同、结局数量 |

## 剧情设计

### 一句话

记忆修复师接下一单生意：修复一位母亲破碎的记忆。他在记忆碎片里看到二十年前一桩儿童失踪案，而所有证据都指向——当年删掉目击者记忆的人，就是他自己。

### 分支为什么"真的不同"

不是换文本再汇合，而是**换整章**：

| 第一章末的选择 | 第二章走向 | 内容差异 |
|---|---|---|
| 隐瞒，自己查 | 地下记忆库 | 潜入、通风井、老档案员、被划掉的名录 |
| 坦白，一起查 | 市政厅旧档案室 | 铁皮箱、录音带、母亲的共谋 |

终章的选择决定结局：

| 终章选择 | 第一章选择 | 结局 |
|---|---|---|
| 删除自己的记忆 | 任意 | **永夜** —— 回到开头，循环 |
| 保留记忆 | 隐瞒 | **回声** —— 独自把真相寄出去 |
| 保留记忆 | 坦白 | **归还** —— 把记忆还给母亲 |

真结局「归还」需要「坦白 + 保留」的组合，并且会额外解锁一段关于女孩下落的线索。

### 变量系统

除硬岔路外，还有两个隐性变量影响结局独白与结案摘要：

- `trust`（与委托人的信任）
- `integrity`（记忆完整度，即你找到了多少碎片）

## AIGC 使用说明

### 用了什么、各自负责什么

| 环节 | 工具 / 模型 | 负责的事 | 产出 |
|---|---|---|---|
| 剧本正文 | 大语言模型 | 生成初稿、扩写描写、统一叙事语气 | `src/content/story.json`，7,200 字 |
| 场景插画 | 图像生成模型（ImageGen） | 按固定 style token 生成统一的电影质感场景图 | `public/assets/bg/*.jpg` 共 8 张 |
| 自由行动裁定 | 大语言模型（OpenAI 兼容） | 读懂玩家自己写的动作，判定它通向哪条支线，并写一段 40-70 字的衔接描写 | `/api/narrate` 实时返回 |
| 结局结案摘要 | 大语言模型 | 根据玩家的完整行动轨迹生成 80-110 字的档案体摘要 | `/api/epilogue` |
| 环境雨声 | **非 AI** | 白噪声 + 低通滤波，用 Web Audio 程序化合成 | 运行时生成，零素材 |

**8 张插画全部是 AI 生成的**，统一提示词模板（同一镜头语言、同一色调、16:9、无人脸）。生成后统一裁掉右下角水印、压到 1600px 宽 / 质量 82，单张 190-275KB。

**没有使用 AI 生成的部分**：界面代码、剧情图引擎、分支结构设计、提示词与白名单约束、音频合成逻辑。素材里没有任何第三方图片或音乐。

### 运行时模型怎么用（这是重点）

自由行动不是"套个对话框"，而是**受约束的叙事裁定**：

```
玩家输入任意动作
      ↓
后端把「当前场景原文 + 玩家动作 + 候选支线」交给模型
      ↓
模型返回 { nodeId, verdict, narration }
      ↓
服务端校验 nodeId 是否在白名单内（不在就用 fallback）
      ↓
前端把 narration 作为"叙事裁定"卡片展示，再进入对应支线
```

核心约束是 **`nodeId` 只能取预定义的白名单**。模型可以自由写描写，但**不能发明剧情分支**，所以永远不会跑飞、不会烂尾。这就是"把模型用进产品"和"把产品交给模型"的区别。

无 Key 时的降级不是"随便选一个"：用中文二元组相似度把玩家输入和每个候选支线的文本比对，取最接近的那条（实测"调监控 / 查日志 / 问她"能分别命中三个不同分支）。

## 工程说明

### 技术栈

- **前端**：React 18 + TypeScript + Vite 5，零 UI 库、零状态库（`useReducer` + 纯函数引擎）
- **后端**：Express 4，单文件代理模型调用 + 托管静态资源
- **测试**：Vitest
- **素材**：jimp（构建期压缩）

选 React + Vite 而不是 Next.js：这是个纯客户端状态机，没有 SSR 需求，Vite 冷启动更快、产物更小（gzip 后 JS 66KB）。选 Express 而不是 Serverless：模型 Key 必须留在服务端，且要能"一条命令启动"。

### 目录结构

```
├─ src/
│  ├─ engine/           # 纯函数剧情引擎（可单测，不依赖 React）
│  │  ├─ types.ts
│  │  ├─ reducer.ts     # 状态迁移 + 存档序列化
│  │  └─ validate.ts    # 剧情图静态校验
│  ├─ content/
│  │  ├─ story.json     # 全部剧情数据
│  │  └─ endings.ts
│  ├─ ai/client.ts      # 前端调后端 + 超时 + 兜底
│  ├─ audio/rain.ts     # Web Audio 合成雨声
│  ├─ hooks/            # 打字机、图片预加载
│  ├─ ui/               # 舞台 / 对白 / 选项 / 自由行动 / 裁定浮层 / 结局
│  └─ App.tsx
├─ server/
│  ├─ index.ts          # 静态托管 + SPA fallback
│  ├─ api.ts            # /api/narrate、/api/epilogue、/api/health
│  ├─ llm.ts            # OpenAI 兼容调用 + 超时 + JSON 容错解析
│  └─ story.ts
├─ scripts/
│  ├─ validate-story.ts # 构建前体检
│  └─ optimize-assets.ts
└─ public/assets/bg/    # 8 张场景图
```

### 流畅度做了哪些事

1. **预加载下一场景**：按 `next` 指针提前拉取背景图
2. **背景图压缩**：17MB → 1.8MB
3. **模型调用 9 秒超时**：AbortController，超时立刻降级，不让玩家盯骨架屏
4. **打字机可跳过**：点击立即补全，再点才推进
5. **选项 450ms 冷却**：防止玩家连点推进时误选
6. **所有异步都有降级**：断网、无 Key、模型返回垃圾，都能继续玩

### 防断链

`npm run validate` 会在构建前检查：所有 `next` / 选项 / 白名单指向的节点是否存在、是否有死胡同、从起点是否可达、结局数是否达标。单元测试里还会用决策表把三条路线**真的走一遍到结局**，任何断链都会让测试红掉。

## 已知问题

1. **无 Key 时理解力有限**：本地裁定靠字面相似度，"我把值班表翻出来"这类委婉说法可能落到兜底分支（不会卡死，但可能不是你想要的走向）。
2. **未做真机测试**：响应式已适配到 720px 以下，但没在 iOS Safari 实机验证过。
3. **只有一个自动存档**：没有多存档槽与手动读档。
4. **没有配乐**：只有合成的雨声底噪，没有 BGM。宁可不放，也不想塞一段风格不搭的 AI 音乐。
5. **模型输出偶发不合规**：已被白名单 + 长度校验兜住，但极端情况下的描写质量不稳定。
6. **自由行动无历史上下文**：每次只把当前场景传给模型，不传完整对话历史（为了控制延迟与成本）。

## 设计取舍

如果只能说明三件事：

**第一，文本骨架人工锁定，只让模型负责局部。** 主线、分支、结局全部写死在 JSON 里，模型只在 3 个自由行动点做"怎么走过去"的裁定。这牺牲了一部分"AI 即兴"的想象空间，换来的是**任何一次通关都不烂尾**——而笔试题明确把"烂尾"列为扣分项。

**第二，Key 必须待在服务端。** 前端直连模型会让 Key 暴露在浏览器里，评审一眼就能看到。多写 80 行 Express 换来的是：Key 安全、可超时、可降级、可观测（`/api/health` 直接看到模型是否接上）。

**第三，把"降级"当成功能做，而不是兜底。** 无 Key 时不是弹个错误框，而是用本地相似度给出一个合理的走向，并用「记忆回溯 · 本地推演」的措辞把它融进世界观。评审在自己机器上没配 Key 也能完整玩通——这比多一个炫技功能有用得多。
